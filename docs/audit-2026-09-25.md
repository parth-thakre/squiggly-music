# Squiggly audit, 25 September 2026

Read-only audit of the uncommitted working tree (desktop app, audio host, connector, browser build, packaging, and release pipeline). Findings were established by source review and targeted in-memory checks; none was reproduced through a running GUI.

## Executive assessment

The desktop security boundary and isolated audio host are stronger than the new renderer workflows. The main release blockers are an unauthenticated credentialed browser preview, playlist mutations that can change the wrong songs, and local playback whose controls remain hidden behind login. Several smaller failures come from treating a track ID, array reference, or queue index as playback identity. Tests cover native and connector behavior well, but scarcely exercise the actual player UI. No critical vulnerability was established, and no live RAM, hardware-audio, or packaged-install performance claim was verified.

## Verification performed

- `npx tsc --noEmit`: passed.
- `npx vitest run`: 211 passed, 2 skipped, seven test files.
- No package builds, application launches, server management, commits, or source changes.
- In-memory checks reproduced both registry-disposal defects.
- Effect Schema decoding confirmed 500-song play requests pass while 501, 600, and 1,000-song requests fail.
- Release files were changing concurrently; packaging conclusions describe the inspected versions.

The native test forks an existing compiled artifact, so a no-build run does not prove a freshly built host works ([tests/native.test.ts:27](../tests/native.test.ts#L27)). The two real-libmpv tests are conditional (lines 49 and 112).

## Fix first

All ten are confirmed implementation defects.

| Rank | Severity | Finding, failure, and fix |
|---|---|---|
| 1 | High | **Authenticate the credentialed preview.** Anyone reaching the port can list and delete playlists, overwrite the saved queue, submit play reports, and stream media as the configured account. A missing Origin passes, and a forged matching Origin passes. Bind to loopback by default and authenticate every API and media route. [navidrome-preview.ts:23–38, 106–125](../scripts/navidrome-preview.ts#L23); [package.json:11](../package.json#L11). |
| 2 | High | **Serialize playlist mutations.** Remove A, then remove C before the first request completes: the requests can reach the server in the other order and remove B instead. An older failure can also roll back a newer success. Queue mutations per playlist (including context-menu edits) and reconcile with server state. [views.tsx:322–328, 353–360](../apps/desktop/renderer/src/app/views.tsx#L322). |
| 3 | High | **Invalidate playlist detail after edits.** Editor mutations invalidate `playlists`, not `playlist:<id>`. Reopening shows deleted songs, and a later reorder can write them back. Update detail and collection caches together. [views.tsx:309–338](../apps/desktop/renderer/src/app/views.tsx#L309); [menu.tsx:32, 127](../apps/desktop/renderer/src/app/menu.tsx#L32). |
| 4 | High | **Show playback controls without a server connection.** "Play files from this computer instead" starts native playback, but the app still renders only the connect screen. Gate library access, not the deck, queue, volume, output, or errors, and handle the `openFiles()` result. [App.tsx:35–39, 283](../apps/desktop/renderer/src/app/App.tsx#L35). |
| 5 | Medium | **Keep queue identity stable across unchanged snapshots.** IPC delivers a new queue array every 250 ms, and TrackTable's `[tracks]` effect clears multi-selection and the Shift anchor each time. Reconcile selection only on structural change, by queue-entry identity. [TrackTable.tsx:35](../apps/desktop/renderer/src/app/TrackTable.tsx#L35); [player.ts:48–55](../apps/desktop/renderer/src/app/player.ts#L48). |
| 6 | Medium | **Make queue limits consistent without changing song identity.** A 600-song playlist cannot play on desktop because all IDs go to the 500-entry request. The web build accepts larger lists but saves only the first 1,000 and clamps the index, so song 1,200 at 60 s resumes as song 999 at 60 s. Define one bounded queue/window policy and translate indexes explicitly. [validation.ts:62](../packages/core/validation.ts#L62); [player.ts:162–166, 203–206](../apps/desktop/renderer/src/app/player.ts#L162). |
| 7 | Medium | **Carry queue-entry identity into selection and seeking.** Clicking the second A in `[A, B, A]` selects the first A because only the ID reaches the host. Dragging during A and releasing after B has started seeks B to A's position. Select by entry; capture the gesture's identity at pointer-down and cancel when it changes. [player.ts:282–300](../apps/desktop/renderer/src/app/player.ts#L282); [host.ts:194–198](../packages/player-mpv/host.ts#L194); [Squiggle.tsx:55–63](../apps/desktop/renderer/src/app/Squiggle.tsx#L55). |
| 8 | Medium | **Move desktop radio into the main process.** Hiding the main window stops its snapshots, so radio stops topping up in mini or tray mode. A late recommendation request can also append to a newer station, because completion only checks that radio is on. Use main-owned state with station generations. [player.ts:63–80](../apps/desktop/renderer/src/app/player.ts#L63); [index.ts:107–110, 515–519](../apps/desktop/main/index.ts#L107). |
| 9 | Medium | **Track browser play reports by playback instance.** Replaying A at the same index sends no new report; moving an already-counted A to another index can report it twice. The browser also counts songs of 30 s or less, unlike desktop. Share the duration rule and mint a playback token on each real load. [player.ts:88, 96–119, 246–263](../apps/desktop/renderer/src/app/player.ts#L88); [plays.ts:4–5](../apps/desktop/main/plays.ts#L4). |
| 10 | Medium | **Fix keyboard editing in menus and add non-drag reordering.** Rename and New playlist remove the focused button without focusing the input; ArrowLeft then navigates the submenu instead of moving the caret, and closing doesn't restore focus. Queue and playlist order can only be changed by dragging. [menu.tsx:53–100](../apps/desktop/renderer/src/app/menu.tsx#L53); [TrackTable.tsx:72–93](../apps/desktop/renderer/src/app/TrackTable.tsx#L72). |

## Other correctness findings

- **Medium, confirmed: browser history becomes inconsistent.** History state stores `stack.length`, but the stack caps at 50. After the cap, consecutive entries share a depth and Back is ignored; Forward after Back is also ignored. Use monotonic entry IDs and a separate cursor. [route.ts:18, 38–46, 65–66](../apps/desktop/renderer/src/app/route.ts#L18).
- **Medium, confirmed: returning to Search restores the results but not the query field,** and a pending debounce can navigate back to Search after another section was chosen. Sync from the restored route and cancel stale timers. [App.tsx:72–86](../apps/desktop/renderer/src/app/App.tsx#L72).
- **Low, confirmed: the mini player overwrites the saved pin preference** by starting pinned and writing that at once. It also never shows engine failures. Initialize from the window's real state and add a compact error state. [Mini.tsx:14–39](../apps/desktop/renderer/src/app/Mini.tsx#L14).
- **Medium, risk: queue restore or reset racing an in-flight save.** An older save can finish after `markSaved` or a reset and record a stale marker; shutdown clears the server while a final save may still be queued. Test delayed completion across restore, reset, and quit, and make completion generation-aware. [queueSync.ts:43–49, 75–80](../apps/desktop/main/queueSync.ts#L43); [index.ts:73–76, 646–652](../apps/desktop/main/index.ts#L73).
- **Low, risk: deep Records scroll restoration.** Records remounts empty with its first page while Back restores the old offset, and the sort and loaded pages aren't in route state. [views.tsx:58–89](../apps/desktop/renderer/src/app/views.tsx#L58); [route.ts:42–45](../apps/desktop/renderer/src/app/route.ts#L42).

Verified non-finding: desktop and web downward queue-move math is correct; the host's `to + 1` matches mpv's insert-before semantics ([queue.ts:31–38](../packages/player-mpv/queue.ts#L31)).

## Security and privacy

Beyond the preview authorization flaw, the desktop controls are good:

- Sender validation checks the registered `webContents` and its main frame. Both windows are sandboxed with context isolation, no Node integration, blocked popups and navigation, and denied permission requests. [index.ts:261–267, 456–464, 623](../apps/desktop/main/index.ts#L261).
- Snapshots exclude authenticated stream locations; connector errors use authored messages. Artwork uses a fixed endpoint, encoded parameters, a raster MIME allowlist, redirect rejection, and `nosniff`. No arbitrary-host SSRF through the preview was found. [client.ts:201–249, 415–429](../packages/adapter-opensubsonic/client.ts#L201).
- The CSP restricts scripts to self and disables objects and form submission. [index.html:9](../apps/desktop/renderer/index.html#L9).
- LRCLIB requires the stored, default-off setting as well as the caller's request, and sends song metadata only. [index.ts:350–352](../apps/desktop/main/index.ts#L350); [lrclib.ts:109–115](../packages/lyrics/lrclib.ts#L109).
- Settings writes are validated, serialized, atomic, and mode 0600 (file contents only, not directory permissions or Windows ACLs). [store.ts:12–29](../apps/desktop/main/store.ts#L12).
- MPRIS publishes title, artist, album, duration, and local artwork, with opaque track paths rather than server URLs. That exposes listening metadata to the desktop session by design, not credentials. [mpris.ts:73–89](../apps/desktop/main/mpris.ts#L73).

**Medium, latent session-isolation risk:** renderer caches, favorite overrides, palettes, and mixes aren't keyed by `sessionId` or cleared when the connection changes, and artwork has a one-day sessionless cache. A reconnect to another account could show that account's metadata where IDs overlap. There is no account-switch control today, so this is a lifecycle risk rather than a reachable exploit. [library.ts:9–24](../apps/desktop/renderer/src/app/library.ts#L9); [favorites.ts:6–18](../apps/desktop/renderer/src/app/favorites.ts#L6); [index.ts:100](../apps/desktop/main/index.ts#L100).

## Audio honesty

**Medium, confirmed:** the browser can retry an unsupported original as MP3, but the signal sentence still names the library's FLAC or ALAC metadata as what the browser decoded, and Song details always says "Streamed from Navidrome as the original file." Separate source metadata from delivery, disclose the fallback, and say "original requested" rather than claiming verified original delivery. [player.ts:148–152](../apps/desktop/renderer/src/app/player.ts#L148); [App.tsx:236–244](../apps/desktop/renderer/src/app/App.tsx#L236); [menu.tsx:225](../apps/desktop/renderer/src/app/menu.tsx#L225).

Native behavior uses null for unknown formats, caps volume at unity, disables default processing, and names exclusivity `exclusiveRequested`. Neither matching sample rates nor that flag proves DAC behavior. Lyrics are line-synced, not word-synced.

## Performance and RAM

- **Medium, confirmed mechanism (cost unmeasured):** App selects the current Track object, which every desktop snapshot replaces, so App re-renders its unmemoized View subtree several times a second. Keep metadata references stable, or separate the deck from the library shell. [player.ts:48–55](../apps/desktop/renderer/src/app/player.ts#L48); [App.tsx:25–38](../apps/desktop/renderer/src/app/App.tsx#L25).
- **Medium, confirmed:** Records keeps every loaded album and renders every card; Artists renders the whole list, and its grouping loop copies growing arrays. Virtualize both and bound pagination. [views.tsx:75, 112–124, 166–189](../apps/desktop/renderer/src/app/views.tsx#L75).
- **Low, confirmed:** favorite overrides never evict; drawn mixes have no cap; the 120-entry library cache is bounded by entries, not tracks or bytes. [favorites.ts:6–18](../apps/desktop/renderer/src/app/favorites.ts#L6); [mixes.ts:54–57](../apps/desktop/renderer/src/app/mixes.ts#L54); [library.ts:8–23](../apps/desktop/renderer/src/app/library.ts#L8).

Track windowing matches the 44 px row height, artwork is requested near display size, palette sampling uses 64 px art, palettes cap at 200, and the main process's track map caps at 20,000. The renderer bundle was 299,188 bytes (93,107 gzip). No live process-count or RAM benchmark was run.

## Accessibility and design

- **Medium, confirmed contrast failures:** palette checks use the base ground, but selected rows add a 16% ink overlay. For a solid red cover, soft text fell from 5.64:1 to 3.67:1 on a selected row. The accent threshold is 3.2:1, yet it colors normal-weight 22 px lyrics, which need 4.5:1 (that example gave 3.56:1). Validate real background combinations and add a text-accent token. [palette.ts:57–75](../apps/desktop/renderer/src/app/palette.ts#L57); [app.css:146–152, 242, 268–277](../apps/desktop/renderer/src/app/app.css#L146).
- **Medium, confirmed:** paused scrubbing updates only a ref, so the thumb, clock, and `aria-valuetext` stay stale until release. Redraw on input. [Squiggle.tsx:47–63](../apps/desktop/renderer/src/app/Squiggle.tsx#L47).
- **Medium, confirmed:** phone layouts hide the Settings entry; the only other route is a link shown under LRCLIB lyrics. [app.css:357–388](../apps/desktop/renderer/src/app/app.css#L357); [lyrics.tsx:53](../apps/desktop/renderer/src/app/lyrics.tsx#L53).
- **Low, confirmed:** menu and sheet entrance animations are missing from the reduced-motion overrides. [app.css:209–236, 446–450](../apps/desktop/renderer/src/app/app.css#L209).
- **Medium, confirmed:** `tracksOf` turns failed requests into empty lists and can silently drop an artist's failed albums, contradicting "every failure is shown." [menu.tsx:29–36](../apps/desktop/renderer/src/app/menu.tsx#L29).

The typography, artwork treatment, shared wave motif, restrained buttons, and shared tokens form a consistent system; fix the interaction defects rather than adding selection chrome. The README still says the browser build cannot play audio and lists queue editing, lyrics, exclusive output, and installers as unimplemented ([README.md:118, 169](../README.md#L118)).

## Tests and release readiness

The suite covers schemas, connector fixtures, native queue semantics, play reporting, queue sync, store permissions, lyrics parsing, MPRIS, and volume coalescing. The new renderer is the main gap: Playwright still targets the old mockups ([mockups.spec.ts:3–15](../tests/ui/mockups.spec.ts#L3)). Add regression tests for playlist sequencing and cache reconciliation, duplicate queue entries, snapshot-stable selection, browser playback and reporting identity, history Back/Forward, menu text editing, and accessible reordering. Keep build-before-test, and add a source-only command so contributors know which tests need compiled output ([package.json:14–18](../package.json#L14)).

Packaging findings are readiness gaps, not proven exploits:

1. **Medium:** CI builds Windows artifacts without launching the packaged app or runtime, and Fedora tests use system libmpv. Add packaged Windows and installed-RPM smoke tests. [release.yml:22–54, 91–122](../.github/workflows/release.yml#L22).
2. **Medium:** Node checksums come from live, unsigned metadata on the same origin as the download, and Windows Koffi integrity comes from live registry metadata rather than the lockfile. Pin expected digests or verify upstream signatures. Cache hits skip rehashing. [fetch-windows-runtime.mjs:22–53](../scripts/fetch-windows-runtime.mjs#L22); [fetch-linux-runtime.mjs:27–49](../scripts/fetch-linux-runtime.mjs#L27).
3. **Medium:** Windows builds are unsigned and attestations are conditional; checksums prove integrity, not the publisher. Update metadata is generated but no updater exists. [release.yml:176–196](../.github/workflows/release.yml#L176); [electron-builder.yml:19–26](../electron-builder.yml#L19).
4. **Medium:** the Windows package includes the libmpv DLL but only Node's license. Resolve libmpv and FFmpeg notices and corresponding-source obligations before distribution. [fetch-windows-runtime.mjs:61–66](../scripts/fetch-windows-runtime.mjs#L61); [electron-builder.yml:43–46](../electron-builder.yml#L43).

`asar: false` is deliberate, since plain Node can't read ASAR archives; it adds unpacked files but isn't a vulnerability, and ASAR isn't a security boundary. The Linux package bundles Node and depends on Fedora's `mpv-libs`, so it's a Fedora-specific package. Release strengths: SHA-pinned actions, empty default permissions, non-persistent checkout credentials, publish-only write permissions, checksum verification before publishing, and a committed libmpv archive digest.

## Extensibility readiness

**Low today, important before plugins, confirmed:** registry disposal is unsafe. Calling a menu disposer twice removes the last, unrelated item (`indexOf` returns −1). Registering a replacement command under the same ID and then disposing the old one deletes the replacement. Both reproduced against the real module. Make disposal idempotent and identity-checked, and define a collision policy. [registry.ts:35–41](../apps/desktop/renderer/src/app/registry.ts#L35).

Next:

- Give each contribution an owner and namespaced ID, with one disposable scope per extension.
- Register built-in commands and route shortcuts through the command registry; today shortcuts call the player and navigation directly and the command map has no consumer. [App.tsx:44–55](../apps/desktop/renderer/src/app/App.tsx#L44).
- Centralize error handling for menu labels, predicates, submenus, and actions, so a failing extension can't strand a loading menu. [menu.tsx:72–103](../apps/desktop/renderer/src/app/menu.tsx#L72).
- Reconcile the trust model: PROJECT.md promises isolated, capability-scoped plugins without Node or credential access, while the chosen direction is full-trust TypeScript extensions. A separate process can still isolate crashes but must not be described as a sandbox. [PROJECT.md:130–138](../PROJECT.md#L130).
- Expose a validated theme-token contract instead of the incidental CSS variables App rewrites from artwork, preserving contrast for selected and active states. [App.tsx:28–30](../apps/desktop/renderer/src/app/App.tsx#L28).

## Suggested next steps

1. Close the preview authorization hole before sharing it on any network again.
2. Fix playlist sequencing and cache reconciliation, with regression tests.
3. Make local playback usable without a server; establish queue-entry and playback-instance identity.
4. Share queue bounds and reporting rules across modes, and move desktop radio into the main process.
5. Add real-renderer interaction tests, then fix menu focus, reorder alternatives, history, and contrast.
6. Stabilize snapshot references and virtualize the album and artist views before claiming library-scale or RAM targets.
7. Gate publishing on packaged smoke tests, and settle runtime verification, signing, and redistribution obligations.
8. Fix registry lifecycle semantics and settle the extension trust model before building an installer or catalog.
